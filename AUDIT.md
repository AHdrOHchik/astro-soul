**Как повторить подсчёт.** Область — `apps/web/src packages/ui/src`. Сырой grep из задания по `#…|rgba?\(` даёт **29 строк**, включая TS/тесты, это не 29 цветов. Для чистой метрики взять все `*.css`, убрать `/\*…\*/`, извлечь уникальные значения деклараций `font-size` и `border-radius` до `;` или `}`, разрешить ссылки через `:root`; для цветов считать совпадения `#[\da-fA-F]{3,8}\b|rgba?\([^)]*\)` и множество уникальных совпадений. Размеры в px непосредственно в декларациях `font-size`: 0. Guard от сырых значений уже есть ([apps/web/tests/design-system.test.ts:97](apps/web/tests/design-system.test.ts#L97)).

**Кадр и hit-test, не макет.** Headless Chromium, штатный `API_MOCK=1`, новый пользователь, browser host, без системных inset. Нет натурных замеров FPS, Lighthouse, времени первого полезного экрана на 4G и переключения живых тем; не выдаём бюджет JS за скорость устройства.

## 3. Предлагаемая дизайн-система (что меняем, что оставляем)

1. **Не создавать второй набор компонентов.** Сохранить `Screen`, `Button`, `Card`, `StateView`, `Skeleton`, `FieldMessage`, rem-шкалу и эмблему. Новая работа — один адаптер платформы и явная область для табов; формы и биллинг используют прежние обработчики. Нижний inset принадлежит либо футеру, либо nav, не обоим. На desktop те же 480 px. На basic host без SDK — CSS env и высота доступной области; `100vh` сейчас **последний fallback**, не основной режим ([Screen.module.css:5–8](packages/ui/src/Screen.module.css#L5-L8), [theme.css:92–116](apps/web/src/theme.css#L92-L116)); для старого WebView заменить его высотой корня/измеренной доступной области, проверить IME. Боковые content-insets в landscape проверить отдельно: сейчас слева/справа учтены только safe-insets.
2. **Токены — роли, а не ночная палитра.** Привязать `bg/surface/text/muted/button/on-button/destructive` к параметрам хоста; для брендового акцента, контура, skeleton и fade подобрать производные поверх **текущего** фона с проверкой контраста. `prefers-color-scheme` только для браузерного fallback, не вместо темы Telegram. Не трогать формулировки для улучшения переносов.
3. **Типографика: решение с ценой в байтах**, не абстрактная просьба «добавить красивый шрифт». Разовый расчёт вне репозитория: `@fontsource/cormorant-garamond@5.3.0`, `cyrillic-600-normal.woff2`, один локальный файл; системный fallback для прочих глифов, включая цифры. Для сравнения к собранному CSS **в памяти** добавлены minified `@font-face` с `font-display:swap` и правило h1. Та же `gzipSync(level:9)`, что у budget guard; это дельта указанной пробы, не обещание размера будущей сборки.

## 5. Риски и что требует решения продукта

- **До продажи обещаний — утверждённый состав подписки (№7).** Нужны решение владельца и версия юридически согласованного текста/каталога, а не копирайт дизайнера. Пока сохраняем фильтры и действующий флаг продаж. Дисклеймер, оферта и согласие неизменны; [apps/web/tests/legal-texts.test.ts:1](apps/web/tests/legal-texts.test.ts#L1) — обязательный регресс.
- **Расхождение с ручной проверкой — не повод исправлять сервер.** На этом HEAD время сброса по месту рождения и обе истории допускают failed (№11–12). Сверить ревизии клиента/API в staging после мерджа, показать один фактический ответ каждого списка и `resets_at` на тестовом аккаунте без передачи ПДн. Если действуют правила брифа, клиент показывает серверный timestamp и прячет внутренние сбои только из списков; согласовать с BE выдачу до `LIMIT`, если скрытые записи вытесняют оплаченные. Никакой клиентской коррекции «на UTC».
- **Город не найден.** Уже есть совет о ближайшем городе; допустима ли такая точность для карты и какую помощь вправе предложить поддержка — решение продукта/расчётчиков. Сначала посмотреть обезличенную долю пустых поисков, не записывать запросы ([BirthPlaceScreen.tsx:54](apps/web/src/screens/BirthPlaceScreen.tsx#L54)). По умолчанию только уточнение ввода/повтор, без координат от пользователя, GPS или автоматической замены города.
- **Явные отличия от дефолтов SKILLS 1.0.** Тема Telegram первична **на всём экране**, не только в системном оформлении. Лимит проекта 350 кБ, не 300; второй шрифт необязателен. Четыре вкладки, не пятый продукт. Бесплатно — три факта при наличии данных; не вводим неделю/месяц, произвольный бесплатный доступ или новый «совет дня». В совместимости — тип отношений и место по контракту, без имени, рейтингов и новых полей. Онбординг — согласие отдельно + три шага; не спрашиваем примерный период у человека, выбравшего «не знаю». Для колеса первым делом доступное чтение существующих данных, не новый движок/sheet/OG-сервис. Для SDK — пакетный мост вместо второго скрипта; `ready` после первого commit и старта `/me`, **не ждёт ответа** ([App.tsx:87–104](apps/web/src/App.tsx#L87-L104), [useRequest.ts:16–28](apps/web/src/hooks/useRequest.ts#L16-L28)): есть скелетон, белый флеш не установлен. Не задерживать splash вслепую. Персистентный offline-кэш прогнозов/CloudStorage — только после решения о ПДн, устаревании, удалении и доступе, не сохранять платный текст «на всякий случай».
- **Что останется неизвестным до QA.** Браузерный baseline не доказывает скорость first-useful <2 с, 60 fps, корректность inset при IME/fullscreen на устройствах, контраст произвольной пользовательской темы, чтение TalkBack/VoiceOver и фактическую конверсию. Для сравнения воронки учесть: `screen_view` зависит от `route`, а вкладки могут меняться внутри `current` ([App.tsx:434–442](apps/web/src/App.tsx#L434-L442), [App.tsx:630–634](apps/web/src/App.tsx#L630-L634)); проверять реальные события по существующим `forecast/ask/settings`, не добавлять PII или новый контракт. Никаких обязательных вопросов, мешающих **аудиту**, не осталось. Перед **правками** нужно подтверждение S1 и свободного окна по файлам.
