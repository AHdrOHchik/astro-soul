# apps/admin — админ-панель «Разбор личности»

Отдельное SPA для владельца продукта и поддержки: найти человека, вернуть
звёзды, откатить разбор, включить/выключить push, безопасно поменять цену —
без разработчика и без SQL. Написана под контракт `api.openapi.yaml` **1.6.14**.

Панель намеренно не входит в бандл мини-аппа: своё приложение, своя сборка,
свой порт, свои тексты. Общих с `apps/web` модулей нет — `apps/web/http.ts`
носит `X-Telegram-Init-Data`, админке нужны cookie-сессия и CSRF-токен.

## Чего здесь нет (и не будет без решения владельца)

- рассылок и любых массовых операций, в том числе «выделить всё»;
- ручного редактирования текстов отчётов;
- выгрузки ПДн списком: данные рождения показываются на одного человека, по
  запросу поддержки, и этот запрос оставляет запись в аудите; CSV — только для
  списков без ПДн;
- собственного SQL и «универсального запроса»: ровно именованные `/admin/*`;
- клиентской арифметики: цена, право на грант и сумма возврата приходят с
  сервера, панель их не пересчитывает и не хранит в константах.

## Запуск

```sh
pnpm install

# с настоящим локальным API (поднятым, например, `pnpm dev:api`)
pnpm dev:admin            # http://localhost:5199, /api/* проксируется на 8080

# без бэкенда — dev-мокер с фикстурами и красной плашкой «ДЕМО»
pnpm dev:admin:mock

pnpm --filter @astro-soul/admin run build      # прод-сборка + страж мока
pnpm --filter @astro-soul/admin run preview    # собранное — на 5299
pnpm --filter @astro-soul/admin run test       # vitest (jsdom)
```

Переменные (`API_MOCK`, `API_PROXY_TARGET`, `ADMIN_DEV_PORT`,
`VITE_TG_BOT_USERNAME`) описаны в `.env.example` в корне репозитория.
`API_MOCK=1` — только `vite dev`: `vite build` с этой переменной падает, а
`scripts/check-no-mock.mjs` дополнительно ищет строки фикстур в `dist`.

## Схема доступа: один origin, никаких исключений

`admin.<домен>` — реверс-прокси на тот же origin, что и API:

```nginx
# правильно: /api/v1/... уходит бэкенду как есть
location /api/ {
  proxy_pass http://api:3000;
}

# НЕЛЬЗЯ: `proxy_pass http://api:3000/;` с косой чертой обрезает префикс
# /api, и каждый маршрут бэкенда отвечает 404. Это самая частая ошибка
# в этой схеме — если панель показывает «нет маршрута» на всём, начиная с
# /admin/me, проверь сначала слэш.
```

Cookie-сессия — `__Host-admin_session`: `HttpOnly`, `SameSite=Lax`, `Secure`
в проде (в dev — по переменной окружения, иначе браузер её выбрасывает на
`http://localhost`). CSRF обязателен на `POST`/`PATCH`/`DELETE` заголовком
`X-Admin-CSRF` — и в dev тоже. CORS нет: он не нужен при одном origin.

## Вход и его отсутствие

Вход: Telegram Login Widget → `POST /api/v1/admin/auth/telegram` (сервер
проверяет HMAC и `ADMIN_TG_ID`, ставит cookie) → `GET /api/v1/admin/me`
(профиль + CSRF) → `POST /api/v1/admin/auth/logout`. Сессия — 12 часов;
`401` от любого запроса гасит её мгновенно, кнопка «Выйти» — в шапке.

**Ни одного из этих трёх маршрутов в контракте 1.6.14 нет.** Поэтому панель
сегодня честно показывает «Вход недоступен: сервер ещё не принимает сессии» и
список недостающих маршрутов; из этого экрана можно открыть только публичную
часть (`/health`, `/founders/count`). До появления серверной части ни один
`/admin/*` маршрут из браузера не работает — это не баг интерфейса.

## Как панель врёт себе и как это запрещено

Правило одно: нет маршрута — нет данных на экране. Номером раздела оно здесь не
ссылается намеренно: номер может измениться, правило — нет. Реестр `src/api/routes.ts`
хранит для каждого адреса `inContract`, и `http.assertCallable` не выпускает
запрос на путь, которого нет в контракте (в dev-моде — с явным флагом
`allowUnknownRoutes`, который в прод-сборке всегда `false`).

- `src/api/routes.contract.test.ts` — тест-страж: сверяет реестр с ключами
  `paths:` из `api.openapi.yaml` и с версией контракта. Маршрут появился в
  контракте, а флаг не поднят, — тест падает.
- `src/ui/Block.tsx` — единственный рендерер состояний: `unavailable`
  («Недоступно в этой версии» + список маршрутов, дети не рисуются), `error`
  (код + `request_id` + причины по полям), пустой ответ («Пусто»). Нули и
  прочерки вместо данных не показывает.
- `src/screens/NotImplemented.tsx` — шесть разделов, у которых маршрутов нет:
  одна строка + перечень того, чего ждёт экран.
- Необратимое действие требует второго шага: `ui/HoldConfirm.tsx` (удержание
  кнопки 2 с) и `lib/confirm.ts` (режим с явным вводом значения). Сегодня это
  работает на отзыве права; для возврата звёзд, смены цены, отключения плана и
  отключения пользователя механизм тот же — но эти экраны появятся вместе с
  маршрутами, их ещё нет.

## Структура

| Путь | Что внутри |
| --- | --- |
| `src/api` | `routes.ts` (реестр + `inContract`), `http.ts` (transport, CSRF, повторы GET), `admin.ts` (именованные вызовы), `types.ts` (выведенные из контракта + две формы вне контракта), `state.ts` |
| `src/auth` | `session.ts` (пять состояний сессии), `telegramWidget.ts`, `tokenStore.ts` (CSRF только в памяти) |
| `src/screens` | `Overview`, `Codes` (коды + история грантов + ручная выдача/отзыв), `NotImplemented` |
| `src/lib` | `format.ts` (ru-локаль, `EMPTY` ≠ `0`), `confirm.ts` (машина двухшагового подтверждения), `selectors.ts`, `router.ts` (свой хеш-роутер), `clipboard.ts` |
| `src/ui` | `Block`, `HoldConfirm`, `Panel`/`Banner`/`Pill`, `CopyChip` |
| `src/i18n/ru.ts` | все тексты интерфейса (хардкода в компонентах нет) |
| `mock/` | dev-мокер и фикстуры (намеренно «некрасивые»: `degraded`, исчерпанный бюджет, молчащий планировщик, отозванные права) |
| `scripts/check-no-mock.mjs` | страж артефакта: в `dist` не должно быть строк мока |

## Что проверять руками после деплоя

`pnpm --filter @astro-soul/admin run build && pnpm --filter @astro-soul/admin run preview`
рядом с поднятым API, затем в браузере: `/api/v1/health` через домен панели
(не напрямую), `/admin/me` → `401` без cookie и `200` с cookie, `POST` без
`X-Admin-CSRF` → `403`. В песочнице браузера нет, поэтому этот шаг — за
человеком.
