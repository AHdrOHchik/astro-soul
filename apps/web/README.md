# apps/web — Mini App «Разбор личности»

Клиент Telegram Mini App. Итерация 1 закрывает экраны 1–5 из `SPEC.md`:
Welcome → BirthDate → BirthTime → BirthPlace → Chart (колесо, три карточки,
тизер разбора, «Поделиться»). Покупка, Report и Paywall (экраны 6–7) — в
следующих итерациях.

Код живёт в двух пакетах:

| Пакет | Что внутри |
| --- | --- |
| `apps/web` (`@astro-soul/web`) | Приложение: экраны, клиент API, обёртка над Telegram, тексты, токены темы, мок API для разработки |
| `packages/ui` (`@astro-soul/ui`) | UI-кит без текстов и без сети: кнопки, поля, карточки, каркас экрана, состояния. Здесь же базовый `tsconfig` фронтенда и его слой правил ESLint (`eslint.frontend.mjs`) |

Из остального монорепо приложение берёт `@astro-soul/shared` (цены планов) и
`api.openapi.yaml` (типы API).

## Запуск

Нужны pnpm 9 (`packageManager` в корневом `package.json`) и Node 22 не ниже
22.22.2: нижнюю границу задаёт jsdom 31, на котором идут тесты, верхнюю (`<23`) —
`engines` корневого `package.json`.

```sh
pnpm install
pnpm --filter @astro-soul/shared build   # один раз и после правок в packages/shared

# с моком вместо бэкенда, в обычном браузере
API_MOCK=1 VITE_DEV_INIT_DATA=mock-init-data pnpm --filter @astro-soul/web dev

# с настоящим API (по умолчанию проксируется http://localhost:8080)
API_PROXY_TARGET=http://localhost:8080 VITE_DEV_INIT_DATA='<initData>' pnpm --filter @astro-soul/web dev
```

`@astro-soul/shared` подключается собранным, из своего `dist/`. Пока он не
собран, не работают ни `dev`, ни `typecheck`, ни `test`, ни корневой `pnpm lint`.
Dev-сервер кладёт пакет в свой кеш зависимостей и изменений в нём не замечает
даже после обычного перезапуска: после пересборки `packages/shared` запускайте
`pnpm dev --force`.

Те же переменные можно положить в `apps/web/.env` (шаблон — `.env.example`,
сам `.env` в git не попадает). `initData` — это учётные данные: строка входит
от имени своего пользователя, поэтому берите её только от тестового аккаунта.
API принимает только строку, подписанную токеном того бота, с которым он запущен
(`TELEGRAM_BOT_TOKEN`), и не старше 24 часов.

Из методов, которые вызывает приложение, в `apps/api` пока есть только
`GET /me`. Поиска места и построения карты там нет, поэтому с настоящим API
приложение доходит до шага «Место рождения» и показывает на нём ошибку; экраны
4–5 целиком работают только с моком.

| Команда (из `apps/web`) | Что делает |
| --- | --- |
| `pnpm dev` | Dev-сервер Vite |
| `pnpm build` | Проверка типов, сборка в `dist/`, затем `scripts/check-bundle.mjs` |
| `pnpm preview` | Раздать собранный `dist/` |
| `pnpm clean` | Удалить `dist/` (его же вызывает корневой `pnpm clean`) |
| `pnpm typecheck` | Сверка типов API с контрактом и `tsc` отдельно для кода приложения и для Node-части (конфиг Vite, мок, тест-охранник) |
| `pnpm test` | Vitest: компонентные и модульные тесты |
| `pnpm size` | Только проверка собранного `dist/` |
| `pnpm gen:api` | Перегенерировать `src/api/schema.gen.d.ts` из `api.openapi.yaml` |

Из корня репозитория `pnpm build | typecheck | test` запускают одноимённые
скрипты во всех пакетах; корневому `pnpm test` нужна ещё и тестовая база для
`apps/api` (см. корневой `README.md`).

Линт один на весь монорепо: `pnpm lint` из корня. Своего конфига ESLint у
фронтенда нет. Корневой `eslint.config.mjs` подключает слой
`packages/ui/eslint.frontend.mjs`, который добавляет к общим правилам
`strictTypeChecked` из typescript-eslint и правила React Hooks — только для
`apps/web` и `packages/ui`. `eslint` в `devDependencies` пакета `packages/ui`
закрывает peer-зависимость `eslint-plugin-react-hooks`. Диапазон версий там
должен совпадать с корневым: с другим диапазоном pnpm ставит в репозиторий
вторую копию ESLint.

## Переменные окружения

| Переменная | Где действует | Назначение |
| --- | --- | --- |
| `VITE_API_BASE_URL` | бандл | Origin API без `/api/v1`. Пусто — тот же origin, что у страницы |
| `VITE_DEV_INIT_DATA` | только dev-сборка | Строка `initData` для запуска вне Telegram. В продакшен-бандл не попадает: `pnpm build` падает, если попала |
| `API_PROXY_TARGET` | dev-сервер | Куда проксировать `/api`, когда мок выключен |
| `API_MOCK` | dev-сервер, `vite preview` | `1` — отвечать моком из `mock/` |
| `API_MOCK_DELAY` | мок | Задержка ответа в мс (по умолчанию 400), чтобы были видны состояния загрузки |
| `API_MOCK_ME` | мок | Сценарий `GET /me`: `returning`, `401`, `500`; иначе новый пользователь |

Секретов у клиента нет. Вход — только по `initData`: приложение держит строку
в памяти и отправляет заголовком `X-Telegram-Init-Data`, токенов не получает и
ничего не кладёт в `localStorage` и cookie. Сам SDK Telegram сохраняет копию
параметров запуска (в них есть `initData`) в `sessionStorage` вкладки, чтобы
пережить перезагрузку страницы; она исчезает вместе с окном Mini App.

## Мок API

`mock/` — middleware dev-сервера, которое отвечает на `/api/v1/*` данными,
типизированными по `src/api/schema.gen.d.ts`: поле, которого нет в контракте,
не пройдёт `pnpm typecheck`. Мок ничего не считает, позиции планет в нём
условные, тексты прямо называют себя демо. В продакшен-бандл мок не входит.

Сценарии включаются вводом на экранах:

| Где | Что ввести | Что произойдёт |
| --- | --- | --- |
| Поиск места | `Мос`, `Каз`, `Нов`, `Сан`, `Ека`, `Вла`, `Кал`, `Алм`, `Мин`, `Амс` | Обычная выдача (поиск по началу названия) |
| Поиск места | любое другое, например `Ъъъ` | `404 GEO_NOT_FOUND` → пустой результат «Ничего не нашли» |
| Поиск места | `ошибка…` | `500` → ошибка с повтором |
| Поиск места | `лимит…` | `429 RATE_LIMITED` |
| Выбор места | `Ошибинск` | `POST /charts` → `500` |
| Выбор места | `Отказово` | `POST /charts` → `422 VALIDATION_FAILED` |
| Выбор места | `Пустошь` | `201` с пустой картой → пустое состояние |
| Выбор места | `Безколёсово` | Карта есть, картинка колеса не грузится |
| Время | «Не знаю» | Карта без Асцендента и домов |

Без заголовка `X-Telegram-Init-Data` мок отвечает `401`, как требует контракт.
Поэтому продакшен-сборка, открытая через `API_MOCK=1 pnpm preview` в обычном
браузере, показывает экран «Открой приложение в Telegram» — так и должно быть.

## Устройство кода

```
src/
  main.tsx          точка входа: тема, Telegram, клиент API
  App.tsx           вход (GET /me) и стек экранов онбординга в памяти
  config.ts         единственное место, где читается import.meta.env
  theme.css         все дизайн-токены; base.css — сброс и базовая типографика
  api/              клиент по контракту: http.ts (заголовки, таймаут, повторы), errors.ts, schema.gen.d.ts
  telegram/         единственный модуль, который импортирует SDK Telegram
  i18n/ru.ts        все тексты интерфейса; format.ts — даты, градусы, числа
  lib/birth.ts      разбор и проверка даты и времени рождения, сборка тела POST /charts
  hooks/            useRequest (запрос + отмена + повтор), usePlaceSearch (поиск с задержкой)
  components/       ErrorState — общий вид ошибки запроса
  screens/          экраны; chart/ — колесо, карточки, тизер
  test/fixtures.ts  выдуманные данные и подставные api/telegram для тестов
mock/               мок API для разработки
tests/              тест-охранник дизайн-системы (Node, без браузера)
scripts/            проверка собранного бандла
```

### Правила, за которыми следят тесты и сборка

- **Токены.** Цвета, размеры, длительности и градиенты задаются только в
  `src/theme.css`; в остальных CSS — только `var(--…)`. Инлайновых `style` нет.
- **Тексты.** Вся кириллица — в `src/i18n/`. В остальном коде приложения и
  UI-кита её нет даже в комментариях (в тестах можно).
- **Старые движки.** В CSS не используются flex-`gap`, `aspect-ratio`, `inset`,
  `:has()`, `:is()`/`:where()`, `@layer`, `@container`, вложенность.
- Всё это проверяет `tests/design-system.test.ts`; он же ловит неопределённые и
  неиспользуемые токены.
- **Контракт.** `pnpm typecheck` (а значит и `pnpm build`) падает, если
  `src/api/schema.gen.d.ts` разошёлся с `api.openapi.yaml`. После изменения
  контракта — `pnpm gen:api`.
- **Бандл.** `scripts/check-bundle.mjs` падает, если `dist/` больше 350 кБ gzip
  (лимит из `SPEC.md`) или содержит dev-переменные.

### Как приложение читает ответы API

- **Ошибки** разбираются по `Problem.code`, а по HTTP-статусу — только если в
  ответе нет тела `Problem` с известным кодом. Поэтому `VALIDATION_FAILED`
  обрабатывается одинаково и с 400, и с 422.
- **Текст ошибки.** `Problem.message` показывается пользователю, только если в
  нём есть кириллица. `apps/api` на неизвестный маршрут отвечает текстом
  фреймворка (`Cannot POST /api/v1/…`) — вместо такого текста приложение
  показывает свой. `request_id` виден на экране ошибки как «Код обращения».
- **Поиск места.** Пустой результат — это `200` с пустым списком или `404` с
  кодом `GEO_NOT_FOUND`. Любой другой `404` считается сбоем, а не «такого места
  нет».
- **Карта без времени рождения.** `asc`, `mc` и `houses` равны `null`
  (контракт 1.1.0). Признак «время неизвестно» — `birth.time_known`, а если
  поля нет, то `asc === null`.

## Поддерживаемые клиенты

Сборка нацелена на Safari 15 (iOS 15) и Chromium 80 (Android WebView). Это
допущение: требований к версиям в `SPEC.md` нет. Vite понижает только синтаксис
и полифилов не добавляет, поэтому код приложения не использует API новее этих
движков, а единственный полифил, без которого SDK на них не стартует
(`Object.hasOwn`), лежит в `src/telegram/polyfills.ts`. Android 9 с ни разу не
обновлённым системным WebView (Chromium 69) не покрыт.

На клиентах Telegram старше Mini Apps 6.1 нет системной кнопки «Назад» —
приложение рисует свою. Если SDK не принимает параметры запуска (он проверяет их
по строгой схеме), приложение всё равно входит по «сырому» `initData` и работает
как веб-страница внутри Telegram: со своей кнопкой «Назад», без перекраски
шапки клиента.

## Проверка на устройстве

Автотесты идут в jsdom, а вёрстка просмотрена в headless Chromium на 390×844 и
320×568. На настоящих клиентах Telegram (iOS, Android, Desktop) приложение не
запускалось. Перед релизом стоит пройти руками:

1. Запуск из бота: экран входа не мигает, шапка и нижняя панель клиента того же
   цвета, что фон приложения.
2. Welcome на маленьком телефоне: дисклеймер 18+ и кнопка видны без прокрутки.
3. Клавиатура на экранах даты и времени: цифровая раскладка, кнопка «Дальше»
   остаётся видна над клавиатурой, фокус сам переходит между полями.
4. Ошибка в поле и предупреждение после «Не знаю» прокручиваются в видимую
   область при открытой клавиатуре.
5. Поиск места: результаты не уезжают под клавиатуру; клавиша «Найти» на
   клавиатуре сворачивает её, а не отправляет форму.
6. Системная «Назад»: возвращает на предыдущий шаг, введённые данные на месте;
   на Welcome кнопки нет.
7. Свайп вниз по содержимому не закрывает приложение (клиенты с Mini Apps 7.7+).
8. Колесо: SVG с сервера показывается в `<img>`, при обрыве сети — блок с повтором.
9. «Поделиться картой»: открывается выбор чата. Отправляется подписанная ссылка
   на SVG колеса. Проверить, что получатель видит в чате: если Telegram не
   строит превью для SVG, это будет голая ссылка, и для шаринга нужен другой
   адрес (PNG, страница с OG-тегами или ссылка на бота) — его нет в контракте.
10. Тёмная и светлая темы клиента: приложение всегда тёмное, контраст шапки в норме.
11. VoiceOver / TalkBack: заголовок экрана читается при переходе, ошибки и
    статус поиска объявляются.

## Что намеренно не сделано в итерации 1

- Покупка полного разбора: кнопка в тизере называет цену, но неактивна. Цена
  берётся из `@astro-soul/shared` (`priceOf('one_149')`) — по `payments.md` это
  единственное место, где хранятся цены. Сам сценарий оплаты
  (`POST /billing/invoice` → счёт Telegram → повторный `GET /me`) относится к
  экранам 6–7, а в `apps/api` этого метода ещё нет.
- Возврат к уже построенной карте: в `GET /me` нет идентификатора карты,
  поэтому вернувшийся пользователь вводит данные заново.
- Аналитика: в контракте нет ни списка событий, ни транспорта.
- Согласие на обработку персональных данных и ссылки на документы: в контракте
  нет ни поля, ни адресов, текстов тоже нет. По AGENTS.md §10 это решает
  человек; до решения экрана согласия в приложении нет.
