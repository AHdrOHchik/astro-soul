# Геоданные: справочник городов

Решение владельца продукта: **геоданные не ходят наружу**. Источник по умолчанию —
собственный справочник в репозитории. Внешние геосервисы — только опция и только
если в справочнике ничего не нашлось.

## Состав справочника

`packages/shared/src/geo/cities.data.ts` (тип `CityRecord`):

* города РФ и СНГ с населением **больше 15 000**, остальной мир — от 300 000 и
  столицы; отсечение по населению, а не «первые N», иначе выпадают целые регионы;
* **названия — русские, из GeoNames с пометкой `isolanguage = ru`** (индекс
  `alternateNamesV2`): «Таллин», «Гуанчжоу», «Сан-Диего», а не «Таллинн»,
  «Гуанжоу», «Сан Диего». Транслитерация — только фолбэк, когда русского
  варианта нет; такие города считаются и перечисляются в `cities.meta.ts`
  (`namesFromRuIndex`, `namesFromCyrillicFallback`, `namesFromLatinFallback`,
  `transliteratedNames` — первые 20);
* обязательные поля записи: `name`, `country` (ISO-3166 alpha-2), `lat`, `lon`, **`tz`** (IANA);
* необязательные: `region`, `population`, `capital`, `aliases` (варианты написания: «СПб», «Saint Petersburg»).

Источник — дамп GeoNames `cities1000` (лицензия CC BY 4.0). Файл **генерируется**
скриптом `packages/shared/scripts/build-cities.mjs` и руками не правится:

```bash
node packages/shared/scripts/build-cities.mjs --fetch   # сборка: дамп + индекс русских названий
node packages/shared/scripts/build-cities.mjs --check   # офлайн-сверка с метаданными
```

`--check` **не требует дампа**: `cities.meta.ts` хранит sha256 файла
`cities.data.ts`, количество записей и версию, и сверка ловит правку руками без
сети и без 470 МБ загрузки. Полная сверка с дампом — `--fetch` и сравнение
отпечатков.

Атрибуция «Содержит данные GeoNames (https://www.geonames.org), CC BY 4.0» — в
шапке `cities.data.ts`, в `cities.meta.ts` и в `README.md`: этого требует лицензия.
Названия регионов приходят из GeoNames на английском («Nizhny Novgorod Oblast»);
перевод регионов на русский — отдельная задача, в справочнике их не переводят.

Часовой пояс (`tz`) обязателен: без него нельзя перевести локальное время
рождения в UTC, а значит и построить карту. Записи без `tz` в справочник не попадают.

Почему данные лежат в `src/`, а не в `data/cities.json`: у `packages/shared`
`rootDir = src`, и JSON за его пределами не попадает в `dist` (API импортирует
пакет, а не файл). Полная сборка при этом генерирует именно этот `.ts` — формат
записи менять нельзя без правки этого документа.

## Статус датасета

Сейчас в репозитории **2 997 городов**, версия
`CITY_DATASET_VERSION = "2026-11-17-geonames-cities1000"` (РФ — 959, СНГ — 664,
остальной мир — 1 374): 2 721 название из индекса `isolanguage = ru`, 210 —
кириллица из дампа, 66 — латиницей (русского варианта нет ни там, ни там). Стартовый набор из 149 городов заменён полной сборкой
из дампа GeoNames: критерий — население, лицензия и версия датасета зафиксированы
в `cities.meta.ts`. Сборка в сеть ходит только при `--fetch` и никогда — при
старте API: справочник лежит в репозитории.

Справочник **не попадает в бандл мини-аппа**: города приходят с сервера, а
границы поиска фронт узнаёт из `GET /me` → `limits` (в пакете от них остались
только типы, `@astro-soul/shared/geo/limits`). Это измерено: было 112,1 кБ gzip,
стало 103,8 кБ.

## Поиск (`POST /geo/resolve`)

* границы длины — **настройка сервера**, не числа в контракте:
  `GEO_MIN_QUERY_LENGTH` (по умолчанию 2) и `GEO_MAX_QUERY_LENGTH` (120).
  Короче или длиннее — `422 VALIDATION_FAILED` с
  `details.field_errors[{field: "query"}]` и `details.reason`
  (`geo_query_too_short` / `geo_query_too_long`);
* клиент узнаёт эти два числа из `GET /me` → `limits.geo_min_query_length`,
  `limits.geo_max_query_length`. Своей копии чисел в клиенте нет: она разошлась
  бы с серверной, и человек получал бы `422` на длине, которую интерфейс считает
  нормой. Поля нет (старый сервер) — клиент не блокирует ввод и полагается на
  `422` с `field_errors[0].field = query`;
* пустой массив означает только «города нет» — за «слишком короткий запрос»
  он больше не отвечает;
* нормализация: регистр, «ё» → «е», пунктуация, «г.»/«город », сжатие пробелов;
* совпадение по началу названия, по началу любого слова и по `aliases`;
* порядок: точное совпадение → начало названия → слово внутри; внутри группы — по населению;
* `limit` по умолчанию `GEO_DEFAULT_LIMIT` (5), потолок `GEO_MAX_LIMIT` (10);
  число больше потолка **молча зажимается** (не `422`): клиент `limit` не
  передаёт, а отказ на подсказке ломал бы поиск;
* **пустой результат — это `200` и `[]`** («такого города нет»), а не 404;
* `503 GEO_NOT_FOUND` — только если недоступен сам провайдер геоданных;
  машинная причина в `details.reason`: `provider_timeout` (не ответил за 2 с),
  `provider_unavailable` (сеть, статус или `429`) или `not_configured` (нет
  контакта для `User-Agent`). **Отсутствие пояса сюда не входит** — это `422`
  (см. ниже): причина постоянная, и повтор запроса не поможет;
* лимит маршрута — 120 запросов в минуту (это чтение: фронт дёргает поиск по мере ввода).

## Провайдеры (`GEO_PROVIDER`)

| Значение | Поведение |
|---|---|
| `bundled` (по умолчанию) | только локальный справочник, никаких сетевых запросов |
| `nominatim` | локальный справочник, при пустом результате — запрос к Nominatim |

Текст ошибки: «Поиск городов временно недоступен. Попробуй ещё раз через минуту.»
Ручного ввода координат в приложении нет и не планируется, поэтому предлагать его нельзя.

Правила для `nominatim`:

* включается только явно через переменную окружения, по умолчанию выключен;
* в запрос уходит название города, **никогда** — дата/время рождения и `telegram_id`;
* обязателен `User-Agent` с контактом (`GEO_CONTACT_EMAIL`), таймаут 2 с;
* фолбэк включается, когда справочник ничего не нашёл **или** нашёл меньше трёх
  кандидатов (одно созвучие — ещё не город); при `bundled` внешних запросов ноль;
* не больше **одного запроса в секунду** (очередь в процессе), ответы кэшируются
  на **24 часа** по нормализованной строке поиска: Redis при заданном `REDIS_URL`,
  иначе память процесса (в логе `geo_cache_unavailable`);
* `429` от Nominatim не повторяем сразу — отдаём `503` с `reason=provider_unavailable`;
* **часовой пояс.** Nominatim, как правило, IANA-пояс не отдаёт, а карта без пояса
  невозможна. Порядок: `timezone` из ответа, если он там есть → иначе пояс
  ближайшего города справочника, но только если он не дальше **300 км**
  (`GEO_TZ_MAX_DISTANCE_KM`, haversine) → иначе город **не отдаётся**:
  `422 VALIDATION_FAILED` с `details.reason = no_timezone` и
  `field_errors[{field: "query"}]` (`geo_tz_unknown` в логах). `503` здесь был
  бы враньём: клиент читает его как «сервис недоступен, повтори», а пояса у
  этой точки нет и не будет;
  Пояс «на глаз» не подставляется никогда: ошибка на час сдвигает время рождения
  и все транзиты;
* если пояс взят у ближайшего города, карта получает предупреждение
  `approximate_place` — механизм `ChartResponse.warnings` уже существовал, новый
  код не понадобился. В логах это `geo_timezone_approximate`.

## Скорость, кэш и лимиты Nominatim

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `GEO_PROVIDER` | `bundled` | `nominatim` включает фолбэк, `bundled` выключает |
| `GEO_CONTACT_EMAIL` | — | контакт в `User-Agent`; без него фолбэк отвечает `503 not_configured` |
| `GEO_NOMINATIM_TIMEOUT_MS` | `2000` | таймаут запроса (2 с: дольше ждать подсказку бессмысленно) |
| `GEO_NOMINATIM_MIN_INTERVAL_MS` | `1000` | не больше одного запроса в секунду |
| `GEO_CACHE_TTL_SECONDS` | `86400` | кэш ответов на 24 часа |
| `GEO_TZ_MAX_DISTANCE_KM` | `300` | дальше этого пояс по ближайшему городу не подставляем |
| `GEO_MIN_LOCAL_CANDIDATES` | `3` | сколько своих кандидатов считается достаточным ответом |
| `GEO_MIN_QUERY_LENGTH` | `2` | минимум длины запроса; короче — `422` |
| `GEO_MAX_QUERY_LENGTH` | `120` | максимум длины; длиннее — `422` |
| `GEO_DEFAULT_LIMIT` | `5` | сколько кандидатов отдавать, если `limit` не передан |
| `GEO_MAX_LIMIT` | `10` | потолок `limit`: больше — молча зажимаем |
| `REDIS_URL` | — | кэш в Redis; не задан — память процесса |

## Границы задачи

`POST /charts` от справочника **не зависит**: фронт присылает `birth_place`
целиком (`name`, `country`, `lat`, `lon`, `tz`), сервер только валидирует
(включая существование пояса в `Intl`).
