# Геоданные: справочник городов

Решение владельца продукта: **геоданные не ходят наружу**. Источник по умолчанию —
собственный справочник в репозитории. Внешние геосервисы — только опция и только
если в справочнике ничего не нашлось.

## Состав справочника

`packages/shared/src/geo/cities.data.ts` (тип `CityRecord`):

* города РФ и СНГ, столицы и крупнейшие города мира;
* обязательные поля записи: `name`, `country` (ISO-3166 alpha-2), `lat`, `lon`, **`tz`** (IANA);
* необязательные: `region`, `population`, `aliases` (варианты написания: «СПб», «Saint Petersburg»).

Часовой пояс (`tz`) обязателен: без него нельзя перевести локальное время
рождения в UTC, а значит и построить карту. Записи без `tz` в справочник не попадают.

Почему данные лежат в `src/`, а не в `data/cities.json`: у `packages/shared`
`rootDir = src`, и JSON за его пределами не попадает в `dist` (API импортирует
пакет, а не файл). Полная сборка при этом генерирует именно этот `.ts` — формат
записи менять нельзя без правки этого документа.

## Статус датасета

Сейчас в репозитории **стартовый набор** — 149 городов (крупные города РФ, СНГ,
столицы и крупнейшие города мира), версия `CITY_DATASET_VERSION = "2026-11-10-starter"`.
Этого хватает, чтобы фронт не сидел на моках, но полное покрытие («РФ/СНГ > 15 000
человек + все столицы мира») — отдельная задача: скрипт сборки из дампа GeoNames,
фиксация версии датасета, ревью диффа. Сборка не должна ходить в сеть на старте API.

## Поиск (`POST /geo/resolve`)

* минимум 3 символа; короче — `200` и пустой массив (это ещё не запрос, а мигание клавиатуры);
* пустой запрос — `422 VALIDATION_FAILED` с `details.field_errors[{field: "query"}]`;
* нормализация: регистр, «ё» → «е», пунктуация, «г.»/«город », сжатие пробелов;
* совпадение по началу названия, по началу любого слова и по `aliases`;
* порядок: точное совпадение → начало названия → слово внутри; внутри группы — по населению;
* `limit` по умолчанию 5, максимум 10;
* **пустой результат — это `200` и `[]`** («такого города нет»), а не 404;
* `503 GEO_NOT_FOUND` — только если недоступен сам провайдер геоданных;
* лимит маршрута — 120 запросов в минуту (это чтение: фронт дёргает поиск по мере ввода).

## Провайдеры (`GEO_PROVIDER`)

| Значение | Поведение |
|---|---|
| `bundled` (по умолчанию) | только локальный справочник, никаких сетевых запросов |
| `nominatim` | локальный справочник, при пустом результате — запрос к Nominatim |

Правила для `nominatim`:

* включается только явно через переменную окружения, по умолчанию выключен;
* в запрос уходит название города, **никогда** — дата/время рождения и `telegram_id`;
* обязателен `User-Agent` с контактом (`GEO_CONTACT_EMAIL`), таймаут 2 с;
* Nominatim не отдаёт IANA-пояс, поэтому подсказка возвращается только если
  пояс находится в справочнике по названию и стране. Иначе город не предлагается
  (`geo_tz_unknown` в логах): карта с часовым поясом «на глаз» хуже, чем пустой список.

## Границы задачи

`POST /charts` от справочника **не зависит**: фронт присылает `birth_place`
целиком (`name`, `country`, `lat`, `lon`, `tz`), сервер только валидирует
(включая существование пояса в `Intl`).
