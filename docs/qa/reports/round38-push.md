# Итерация 38 — утренний пуш 08:00 (контракт 1.6.13)

Контракт **1.6.12 → 1.6.13**, аддитивно: в `/health.flags` появился `push`, в
`/admin/metrics` — четыре счётчика пуша, в `/admin/alerts` — седьмое правило
`push_failed`, в `JobRunResult` — счётчики пропусков и дублей. `required` нигде не
тронут, существующие значения не переименованы; `Me.notifications` и
`POST /me/notifications` **не менялись**.

Прогон (sandbox, Postgres 5433 / `astro_soul_test`): API **61 файл / 858
тестов** (было 60 / 727), web **51 / 920** — без изменений: PR трогает только
сгенерированную схему (`schema.gen.d.ts`) и не добавляет тестов web; astro
**118** (pytest) — без изменений. `pnpm lint` и `ruff` — чисто, `pnpm build` — зелёный: **16.9 s wall,
27.9 s user + 1.6 s sys**; web **129.9 kB gzip** из бюджета 350 kB.

### Текст (без модели)

```
🌔 Доброе утро.

Луна в Рыбах, растущая — Не начинай того, что можно отложить на завтра.

Разбор дня на 5 минут
```

- первая строка — эмодзи фазы из `PHASE_EMOJI` + `Доброе утро.`;
- вторая — `Луна в <знак>, <фаза> — <фраза>`; фраза берётся из `MOON_ADVICE`
  (те же константы, что карточка `moon` и карточка дня), лимит 120 символов,
  обрезка **по границе предложения**, а если не влезает и оно — остаётся только
  факт;
- третья — всегда `Разбор дня на 5 минут`;
- кнопки — «Открыть разбор дня» (`web_app`, адрес без `startapp` → экран
  «Сегодня») и «Отключить» (`callback_data: push_off`);
- `parse_mode: HTML`, экранируются `& < > "` в знаке и фазе.

Единственная цифра в тексте — «5» в обещанной формулировке «Разбор дня на
5 минут». Тест это фиксирует явно, чтобы запрет «никаких чисел» не протух.

### Решения, которые стоит подтвердить

1. **`push_skipped_no_tz_24h` — состояние, а не поток.** Человека без валидного
   пояса нельзя поставить в окно: 08:00 по местному не вычислить. Считать его
   «пропуском за сутки» значило бы накручивать 1440 в день на одного человека.
   Поэтому метрика отвечает «сколько людей сейчас недостижимо», и это записано
   в контракте. Имя осталось из задания.
2. **`pushes_skipped_inactive` в `JobRunResult` оставлено и всегда `0`.**
   Правило «писать только тем, кто заходил за 7 дней» заменено правилом «не
   писать тому, кто уже открывал приложение после 07:30». Поле не удалено,
   потому что контракт этой итерации аддитивный; новый счётчик —
   `pushes_skipped_seen`.
3. **`last_seen_at` — новая колонка.** В задании она упомянута как существующая,
   но её не было: добавлена миграцией `0033` и заполняется в middleware
   авторизации (не чаще раза в минуту на процесс).
4. **Окно — параметр, а не константа.** `PUSH_SEND_HOUR` / `PUSH_WINDOW_MINUTES`
   из окружения; в коде остались только значение по умолчанию и валидация.

### Тесты

Новый файл `apps/api/test/push-morning.spec.ts` — **134 теста**:

- получатели: карта + согласие + телеграм; без согласия; без карты; испорченный
  пояс → `skipped_no_tz`;
- окно: 07:59 / 08:00 / 08:04 / 08:05 / 09:00;
- идемпотентность: два прогона в одну минуту → одно сообщение; `claimPush`
  дважды → `false` (источник `duplicate_prevented`);
- пояса: `Asia/Novosibirsk` (08:00 местного = 01:00 UTC, и в 01:00 UTC московский
  человек пуша не получает), `Europe/Berlin` в ночь перехода 29.03.2026 — ровно
  одно сообщение, смена пояса карты — следующий пуш по новому поясу, история не
  пересчитывается;
- «не мешать»: `last_seen_at` 07:40 → пропуск, 07:10 → пуш;
- `DELETE /me` → следующий цикл человека не видит, `push_log` пуст;
- ошибки Bot API: 403, 400 `chat not found`, 429 с `retry_after` (ждём и
  продолжаем с того же человека), 429 без конца → `deferred`, 500 — один повтор,
  затем `push_log.error`; 500 после закрытия окна — без повтора;
- `PUSH_ENABLED=0`: нули, никаких `push_runs`, `/health.flags.push.enabled=false`,
  `status: ok`;
- `/health`: включённый пуш без прогонов → `degraded`, после прогона → `ok`,
  прогон старше 2 часов → снова `degraded`;
- `/admin/metrics`: `push_sent_24h`, `push_failed_24h`,
  `push_duplicate_prevented_24h` (из `push_runs`), `push_skipped_no_tz_24h`;
- `/admin/alerts`: 21 провал → `push_failed` warning, 1 провал → не сработал;
- кнопка «Отключить»: флаг снят, подсказка дословно, **ни одного нового
  сообщения**, повтор идемпотентен, в кабинете `daily_forecast: false`;
- присутствие: авторизованный запрос заполняет `last_seen_at`;
- текст: **96 комбинаций** «8 фаз × 12 знаков» — ≤ 200, вторая строка ≤ 120,
  эмодзи фазы, запрещённые эмодзи, числа, `forbiddenTopicIn()`, отсутствие
  обращений по имени и рода; экранирование `Личный рельеф & <тест>`; нет
  `t.me/` / `tg://` / дат.

Изменены существующие спеки (и это в PR осознанно):

- `engagement.spec.ts` — блок `forecast_push` (пуш из текста прогноза, окно
  ±30 минут, фильтр 7 дней, `forecasts.push_sent_at`) заменён маркером со
  ссылкой на новый файл: код, который он проверял, удалён;
- `ops-alerts.spec.ts` — «шесть алертов» → «семь», в порогах `push_failed: 20`.

## 2. Что проверить QA

### Сценарий 1 — пуш на московском аккаунте

1. `PUSH_ENABLED=1`, рестарт API. Аккаунт: карта с `Europe/Moscow`, тумблер
   «Прогноз дня» включён, бот не заблокирован, в это утро приложение не
   открывалось после 07:30.
2. Дождаться 08:00–08:04 по Москве (или поставить `PUSH_SEND_HOUR` на ближайший
   час **на стенде** и перезапустить API).

**Ожидаемо:** одно сообщение `🌓 Доброе утро.` + «Луна в …, … — …» + «Разбор дня
на 5 минут», две кнопки. В `push_log` строка с `error IS NULL`, в `push_runs`
`sent = 1`, в `/admin/metrics` `push_sent_24h` вырос на 1.

### Сценарий 2 — кнопка «Открыть разбор дня»

1. Нажать кнопку в пуше.

**Ожидаемо:** открывается мини-апп на экране «Сегодня»; знак и фаза в пуше
совпадают с тем, что на экране (данные из того же `/forecast/facts` на ту же
местную дату). Ссылка без `startapp` — проверить, что экран не онбординг.

### Сценарий 3 — кнопка «Отключить»

1. Нажать «Отключить».
2. Повторить нажатие.
3. Открыть кабинет → уведомления.

**Ожидаемо:** всплывающая подсказка «Больше не буду присылать. Включить можно в
кабинете»; **в чате не появляется новое сообщение**; в кабинете тумблер
«Прогноз дня» выключен (`GET /me` → `notifications.daily_forecast: false`); на
следующее утро пуша нет; событие `push_disabled` в `events` — одно, даже после
двух нажатий.

### Сценарий 4 — бот заблокирован

1. Заблокировать бота аккаунтом, у которого есть карта и согласие.
2. Дождаться цикла.

**Ожидаемо:** `users.push_enabled = false`, в `push_log.error` — `blocked`
(или `chat_not_found` для 400), в `push_runs.blocked = 1`, `push_failed_24h`
**не растёт** (отказ человека — не поломка), алерт `push_failed` не срабатывает,
повторов на следующий день нет.

### Сценарий 5 — нет карты

1. Аккаунт без карты (`DELETE /me` или новый пользователь, который не построил
   карту), `push_enabled = true`.

**Ожидаемо:** пуша нет ни в один день; в `push_runs.candidates` этот человек не
появляется; ошибок в логах нет.

### Сценарий 6 — выключенная функция

1. `PUSH_ENABLED=0`, рестарт API, дождаться 08:00 по любому поясу.

**Ожидаемо:** ни одного сообщения; планировщик не создан (в логе нет
`push_scheduler_started`); новых строк в `push_runs` нет; `/health` →
`flags.push = {enabled: false, last_run_at: null, last_sent_count: 0}` и `status`
не `degraded` из-за пуша (остальные зависимости в норме). После `PUSH_ENABLED=1`
и рестарта — `enabled: true`, через минуту `last_run_at` не `null`.

### Отдельно: смерть планировщика

Остановить/убить процесс API на 3 часа с включённым пушем. **Ожидаемо:**
`/health` через 2 часа без прогонов → `status: degraded`; в `flags.push`
`last_run_at` не двигается. Это и есть ответ на «как узнаем»: молчание
рассылки не видно никому, кроме `/health`.

## 3. Что осталось непроверенным

- Реальная доставка через Bot API (тесты используют fake): проверено только
  соответствие формата вызова (`parse_mode: HTML`, `reply_markup`, кнопки).
- Поведение при десятках тысяч получателей: пауза 35 мс и бюджет 5 минут в
  тестах не нагружались. Оценка: 25 сообщений на порцию, ~28 сообщений/с.
- `retry_after` в секундах — значение читается из `parameters`, но поведение
  Telegram при повторных 429 проверялось только на подмене.
- Время доставки в разных клиентах Telegram и вид текста на экране блокировки —
  глазами, на устройствах.
