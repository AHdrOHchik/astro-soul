# Разведение событий шеринга и ссылка в бота (контракт 1.6.9, итерация 34)

Мини-итерация. Одна цель: метрика «поделились» должна считать отправки, а не
создания карточек. Плюс два контрактных пробела, без которых фронт не может
сделать шаринг: постоянная ссылка в бота и обработчик inline-запроса.

## Что изменилось

| Было (1.6.8) | Стало (1.6.9) |
|---|---|
| серверное `share_sent` = «карточка сгенерирована» | серверное `share_card_created` = «мы отдали картинку» |
| клиентское `share_sent` невозможно (`422`) | клиентское `share_sent` с закрытыми `props` |
| `ShareCard.url` (подписанная, 24 ч) | `ShareCard.url` + `ShareCard.share_url` (постоянная, в бота) |
| бот отвечает только на `/start sh_<short_id>` | плюс `inline_query` (`switchInlineQuery`) |
| inline-режим нигде не проверяется | `getMe.supports_inline_queries` на старте API |

## Задача 1 — переименование серверного события

`share_sent` → `share_card_created`. Пишется в `POST /share/card`, то есть там,
где карточка действительно отдаётся.

Свойства: `kind`, `bytes`, `cached`, `build_ms` (последнее — только когда
карточку рисовали). Ни получателя, ни текста карточки, ни ссылки.

**Исторические данные.** События за прошлые сутки лежат в `events` под старым
именем и не пересчитываются: счётчик «создано карточек» начинается с этой
итерации. Переписать старые строки нельзя — их смысл был другим (там были
генерации, но имя означало отправки). Объём данных на тестовом этапе ничтожен.

**Счётчиков в `/admin/metrics` это не касается:** `share_sent_24h` не
существовало, переименовывать нечего. Аналитика шеринга считается по `events`.

Проверено тестами: `share_cards.spec.ts` → «`share_card_created` — только вид,
размер и время сборки», «кэш-попадание помечено `cached: true` и не врёт про
время сборки», «сервер не пишет `share_sent`»; `telegram_start.spec.ts` → после
`/start sh_…` в `events` одно событие (`share_card_opened`).

## Задача 2 — клиентское событие `share_sent`

38-е имя в `x-analytics-events`. `props` закрыты:

```yaml
x-event-strict-props:
  share_sent:
    kind: [day, wheel, insight]
    channel: [inline, link]
```

- неизвестное значение или отсутствующее поле → `422`, `field_errors[{field:
  "events.props.kind" | "events.props.channel"}]`, **батч не пишется**;
- лишние ключи вырезаются (проверено тестом: присланный вместе с `kind`/
  `channel` `url` в БД не попадает);
- остальные клиентские события принимают свободные `props`, как раньше.

**Тест на `422` для неизвестного события не ослаблен.** `made_up_event` →
`422` с `events.name`, как и было; произвольные имена по-прежнему невозможны.
Менялся контракт, а не валидация.

Проверено (`events.spec.ts`, +4 теста): валидные `props` → `202 accepted:1` и
запись ровно `{kind, channel}`; `kind: "compat"` → `422`; `channel: "telegram"`
→ `422`; без `props` → `422` на оба поля.

## Задача 3 — `ShareCard.share_url`

`https://t.me/<bot>?start=sh_<short_id>`, собирается на сервере из
`BOT_USERNAME` (тот же конфиг, что у ссылки карты). Клиент имя бота не знает и
хардкодить не должен; `short_id` наружу больше нигде не отдаётся.

`share_url` ≠ `url`:

| | `url` | `share_url` |
|---|---|---|
| что это | файл PNG | бот |
| срок | 24 часа (подпись) | нет |
| уходит в чат | нет | да (текстом) |
| содержит `sig=` | да | нет и быть не может |

`null` — если `BOT_USERNAME` не настроен: собрать ссылку не из чего, а пустая
строка сломала бы fallback молча.

Проверено (`share-cards.spec.ts`, +2 теста): `share_url` совпадает с
`^https://t.me/<bot>\?start=sh_<10 символов>$`, не содержит `sig=` и `/files/`,
а `url` остаётся подписанным; `short_id` в ссылке равен `short_id` строки
`share_cards`, а в самой строке нет ни одного UUID (`user_id`/`report_id`).
`kind: "compat"` → `404` (тест был и остался).

**Срок жизни.** `share_url` бессрочная, а «карточка живёт, пока живёт бот-ответ»:
по ссылке бот достаёт карточку из `share_cards` и выпускает свежую подпись. Если
карточку удалили, бот отвечает «Карточки больше нет» и ведёт в приложение
(`telegram_start.spec.ts`). ПДн в карточке нет, поэтому удаление аккаунта её не
ломает: `DELETE /me` стирает файл вместе со строкой, но текст карточки
восстанавливается из фактов дня.

## Задача 3.1 — inline-режим бота

**Что было.** Бэкенд умел только `/start sh_<short_id>` — это переход по ссылке,
а не inline-запрос. Обработчика `inline_query` в коде не было вообще, поэтому
`switchInlineQuery` не мог привести к карточке **даже при включённом режиме**:
Telegram присылал апдейт, вебхук его игнорировал, человек видел «бот не
отвечает». Это и была тихая поломка основного пути шаринга.

**Что настроено в BotFather.** В репозитории этого нет и проверить из песочницы
нельзя: реального токена бота здесь нет, тесты работают с подменённым Bot API
(`fake-telegram.ts`). Единственный достоверный источник — `getMe` →
`supports_inline_queries`. Теперь он спрашивается при старте API:

```
{"msg":"telegram_inline_mode","state":"off","hint":"inline-режим выключен: switchInlineQuery не откроет выбор чата. BotFather → /setinline, затем перезапуск API не нужен"}
```

Состояния: `on` (INFO), `off` (WARN + подсказка), `unknown` (Bot API не ответил —
«не знаем» ≠ «выключен»).

**Как включить (ручной шаг, кодом не делается):**

1. `@BotFather` → `/setinline` → выбрать бота → placeholder, например
   `Вставь ссылку на карточку`.
2. Перезапуск API не нужен; на следующем старте в логе должно быть
   `state: "on"` (или прогнать диагностику — `getMe`).
3. Проверка руками: в любом чате набрать `@<bot> k7m2p9x4qz` → должен появиться
   один результат — карточка с подписью.

**Что теперь обрабатывается** (`parseInlineQueryShortId`, `telegram-inline.service.ts`):

| Ввод после `@bot` | Ответ |
|---|---|
| `k7m2p9x4qz` | карточка |
| `sh_k7m2p9x4qz` | карточка |
| `https://t.me/<bot>?start=sh_k7m2p9x4qz` | карточка |
| пусто / мусор / `ref_123` / неизвестный `short_id` | пустой список (не молчание) |

Карточка уходит как `InlineQueryResultPhoto` с `caption` (та же строка, что в
`ShareCard.caption`), `photo_url` — свежая подпись на файл. `cache_time: 0`:
подпись выдаётся в момент ответа, лишний вызов дешевле протухшей ссылки.

**Пока inline-режим не включён, основной путь — `share_url` + `openTelegramLink`**
(кнопка отправляет ссылку текстом, получатель открывает бота и видит карточку).
Это записано в задании фронту, а не оставлено на догадки. Событий продукта на
inline нет намеренно: ответ на запрос — показ карточки, а не отправка; «поделились»
считается один раз и по клиенту.

Проверено (`telegram-inline.spec.ts`, 9 тестов): разбор всех трёх форм и отказ
на мусор; ответ одной карточкой с рабочей подписью (`storage.verify` → `ok`) и
размерами 1080×1920; пустой список на неизвестную метку; ноль событий продукта
после inline-ответа; `checkMode` → `on` / `off` / `unknown`; вебхук маршрутизирует
`inline_query` в обработчик.

### Одна строка вне границ

`apps/web/src/analytics/events.ts` → `share_sent: true,`. **Разрешено
владельцем**: bump контракта иначе делает `main` красным (`Record<EventName,
true>` требует все имена и `contract.test.ts` сверяет список), а фронт-агент
блокируется на `gen:api`. Больше в `apps/web` ничего не менялось: ни логики
отправки, ни `track(...)`, ни импортов — отправку события фронт делает в
round33. `contract.test.ts` не тронут, 38 = 38 сошлось само.

## Чего в этой итерации нет

- Маршруты `POST /share/card` и `GET /files/...` не менялись.
- Новых полей в PDF, метриках и `/health` нет.
- Отправку `share_sent` фронт пока не делает — событие объявлено, но приходит
  только от клиента, а его правка — следующая итерация фронта.
- `openTelegramLink` на бэке не проверяется: это клиентский вызов.

1. `POST /share/card {kind: "day"}` → в ответе `share_url` вида
   `https://t.me/<bot>?start=sh_…`, без `sig=`; `url` — наоборот, с `sig=`.
2. Открыть `share_url` в Telegram → бот присылает ту же карточку.
3. Прислать `POST /events` с `share_sent` и `kind: "compat"` → `422` с

4. `made_up_event` → `422` (поведение не изменилось).
5. `POST /share/card` дважды → в `events` два `share_card_created`
   (`cached: false`, затем `cached: true` без `build_ms`) и ни одного

6. Включить `/setinline` в BotFather → перезапустить API → в логе
   `telegram_inline_mode state=on`; набрать `@<bot> sh_<short_id>` → карточка.
   Пока не включено — `state=off` с подсказкой, и это ожидаемо.
