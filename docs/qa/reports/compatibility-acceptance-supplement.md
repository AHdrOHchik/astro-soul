# Дополнение к приёмке совместимости: клиент и актуальная цена

Дата: 2026-11-15 UTC. Ветка `arena/3cca2c4e-astro-soul`, база `6da7b57` (`main`). Это дополнение проверяет клиентский сценарий совместимости и каталог оплаты; `apps/api` не менялся. Браузер/Telegram с реальным backend в этой сессии не запускались.

## A1–A5 — ответы по критериям

| Пункт | Ответ и основание |
|---|---|
| A1 — данные формы партнёра и приватность | Форма не запрашивает имя и отправляет только `relationship` и поля партнёра `birth_date`, `birth_time` (null при неизвестном времени), `place`. Текст приватности на экране проверен точным тестом: «Данные партнёра нужны только для расчёта. Мы не спрашиваем имя и не показываем его. Совместимость хранится вместе с остальными твоими данными и удаляется вместе с ними.» Успешные тесты проверяют также отсутствие лишних ключей и невозможность отправки без выбранного города. |
| A2 — различение ошибок и повтор | `503` с `details.reason=compat_breaker_open` даёт отдельный экран брейкера и бесплатный повтор; `503` с пустой причиной и неизвестные причины остаются на общей retry-ветке. Проверены retry после 500 и network error с теми же введёнными данными. Это тесты с API-моками, не живой backend. |
| A3 — квота | При `left=0` действие «Создать ещё» выключено; при `left=1` доступно. Дата следующей квоты выводится из серверного `resets_at`, клиент не рассчитывает её сам; для отсутствующего `resets_at` показан отдельный нейтральный текст. Тесты проверяют все ветки. |
| A4 — цена и invoice | Источник отображаемой цены — свежий `GET /billing/plans` (`stars`); только при совпадении допустима сумма `POST /billing/invoice` (`stars`, контрактное поле). В `POST /billing/invoice` передаются `plan_code` и применимый `chart_id`, сумма не отправляется. Нет подходящего плана/цены — виден текст «Оплата временно недоступна», кнопки оплаты с ценой нет. Расхождение каталога и invoice блокирует открытие invoice, очищает этот invoice из памяти и предлагает обновить каталог. |
| A5 — аналитика и правки контракта | `price_mismatch_shown` не добавлено: события нет в allowlist клиента и enum OpenAPI, менять `apps/api` запрещено. Вместо него используется уже разрешённое `error_shown { screen: 'paywall', code: 'price_mismatch' }`. Дата рождения, `relationship` и `chart_id` не передаются в событиях: тип `Track` не принимает эти props, `cleanProps` пропускает только `step`, `code`, `field`, `version`, `screen`, `plan_code`, `report_id`. |

## Пять тестовых сценариев дополнения 23б

Все перечисленные сценарии прошли в Vitest с моками:

1. Нет серверного ожидаемого плана/цены — нет оплаты с ценой, показано «Оплата временно недоступна».
2. Цена каталога, включая тестовую величину `1 ⭐`, отображается как есть; клиент не пересчитывает и не округляет её.
3. Создание invoice отправляет `plan_code` и допустимый `chart_id`, но не `stars`/сумму.
4. `invoice.stars !== plans.stars` — invoice не открывается/не кэшируется для повторной оплаты, новая цена из invoice не показывается; экран предлагает обновить каталог.
5. Новое открытие экрана заново вызывает `GET /billing/plans` и использует свежий результат, не кэш сессии.
