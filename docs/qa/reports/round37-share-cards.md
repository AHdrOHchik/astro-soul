## 3. Контракт (1.6.12, аддитивно)

- `ShareCardKind`: `enum [day, wheel, insight, identity, moon]`; описание
  разбито на «сторис» и «старую вёрстку».
- `POST /share/card`: необязательное `tz` (описано, для каких видов

- `x-analytics-events` += `share_saved` (39 событий); `x-event-strict-props`:

- `/admin/metrics`: `share_cards_created_24h` (object, integer по видам).
- `gen:contracts:check` и `gen:api:check` — без расхождений.

## 4. Миграция

`migrations/0032_share_cards_template_version.sql` (единственная):

- `share_cards.template_version text not null default 'classic-1'` +
  бэкфилл: `day` → `legacy-0` (старая вёрстка), остальные — `classic-1`;
- `CHECK` на `kind` пересоздан: `day, wheel, insight, identity, moon`;
- уникальный индекс `(kind, content_hash)` заменён на
  `share_cards_content_version_idx (kind, content_hash, template_version)` —
  две версии одной карточки теперь допустимы;
- `short_id` остаётся уникальным; старые ссылки `sh_<short_id>` открываются.

`IF EXISTS`/`IF NOT EXISTS` — файл можно накатить повторно. Данные, кроме
`template_version`, не переписываются.

**Отклонение (важно):** `short_id` теперь считается от
`(template_version, content_hash)`. Без этого первая же смена шаблона падала на
уникальном индексе `share_cards_short_idx` → `503 share_card_race` (воспроизведено
тестом). Старые `sh_`-ссылки ведут на старую строку и её файл.

```bash

curl -s -X POST -H "X-Telegram-Init-Data: $INIT_DATA" -H 'content-type: application/json' \
```

Фразы проверить глазами: без «асцендент/Солнце в …», без «на 80 %», без

### 5.4. `moon` без профиля

```bash
# новый пользователь бота, карту НЕ строил
curl -s -X POST -H "X-Telegram-Init-Data: $NEW_INIT_DATA" -H 'content-type: application/json' \
  -d '{"kind":"moon","tz":"Europe/Moscow"}' https://<host>/api/v1/share/card | jq '.url, .caption'
# ожидается 200 и картинка; дата совпадает с «Сегодня» в приложении
-d '{"kind":"moon","tz":"Pacific/Kiritimati"}'   # дата — по этому поясу
-d '{"kind":"moon","tz":"Mars/Olympus"}'         # 422 share_tz_unknown, field tz
# без initData → 401
```

**Обязательный сценарий (37.1): «вчерашняя дата».** Фронт теперь передаёт `tz`
всегда; сервер правило не менял, и это надо увидеть глазами:

1. Открыть приложение в 00:30–03:00 по Москве (или в 00:30–07:00 по
   Новосибирску) — окно, где UTC-дата ещё вчерашняя.
2. Карточка `moon` из приложения: на карточке дата = «Сегодня» в приложении,
   фаза и знак совпадают с прогнозом дня на эту же дату.
3. Тот же запрос без `tz` (`curl` выше) у человека **без карты** — дата
   вчерашняя: это ожидаемое техническое умолчание (UTC), а не дефект; оно
   зафиксировано тестом.
4. Если на карточке из приложения вчерашняя дата — фронт не передал `tz`;
   это блокер релиза, а не «мелочь»: карточка `moon` — первая, по которой о
   нас судят.

## 6. Правки по ревью (37.1)

### 6.1. `moon` без `tz` — вчерашняя дата

Правило не менялось: `tz` → пояс последней карты → **UTC**. Изменилось то, что
оно теперь записано в контракте явно и с последствием (`tz` у
`POST /share/card`): клиент обязан передавать
`Intl.DateTimeFormat().resolvedOptions().timeZone` **всегда**, потому что для
UTC+3…UTC+12 UTC-дата до 3–7 утра — вчерашняя. Умолчание UTC выбрано
сознательно: угаданный пояс ошибся бы незаметно, а UTC ошибается предсказуемо и
виден в дате на картинке.

Зафиксировано тестами (`apps/api/test/share-cards-stories.spec.ts`):

| Тест | Что доказывает |
|---|---|
| `без \`tz\` и без карты дата считается по UTC — так и зафиксировано` | дата на карточке = UTC-дата; изменение умолчания молча сломает тест |
| `без \`tz\`, но с картой — пояс карты: правило не менялось` | у человека с картой дата по поясу карты (`Europe/Moscow`) |

QA — §5.4, «Обязательный сценарий: вчерашняя дата».

### 6.2. `MOON_ADVICE` проходит список запрещённых тем

Восемь фраз и запасная строка — совет, а валидатор разбора их не видел
(константы не проходят через `validateSection`).

- `forbiddenTopicIn()` в `reports/validators.ts` — тот же `FORBIDDEN_TOPICS`;
  `validateSection` продолжает пользоваться этим же списком, копии нет.
- `apps/api/test/moon-advice-safety.spec.ts` (6 тестов): список действительно
  ловит известные плохие примеры; каждая фраза и запасная строка дают `null`;
  структура («Не начинай …», без цифр и процентов, ≤ 140 символов); подписи фаз
  совпадают с `PHASES` из `daily.py` (тест читает Python-файл); незнакомая фаза
  даёт запасную строку.
- `packages/astro/tests/test_cards.py` (+11 тестов): **тем же списком** —
  читает `FORBIDDEN_TOPICS` из `validators.ts`, переводит `\p{L}` и флаг `i` в
  Python и **параметризуется по фразам из `share.service.ts`**: девятая фраза
  попадает под проверку сама, без правки теста. Отдельная проверка, что список
  прочитан и ловит `лечение` / `гарантированный доход` / `кармический` /
  «вернётся к концу года» — иначе все остальные проверки проходили бы на пустом
  месте.
- Тип: `MOON_ADVICE: Record<MoonPhaseLabel, string>`, `MoonPhaseLabel` выводится
  из `MOON_PHASES`. Новая фаза без фразы — ошибка компиляции.

Фразы не переписывались: все восемь проходят список как есть. Новое — проверка,
а не текст.
