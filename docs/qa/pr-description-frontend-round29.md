## Что и почему

Кнопка управления подпиской раньше вела на несуществующий Telegram deep link, а квота совместимости могла расходиться с сервером. Этот PR переводит отмену на серверный контракт OpenAPI 1.6.5 и делает квоту совместимости единообразной. Backend не изменялся.

## Что сделано

- Добавлена серверная отмена через `POST /api/v1/subscription/cancel`; UI меняет состояние только после нового `GET /me`.
- Добавлены подтверждение с предупреждением о невозврате звёзд, UUID v4 `Idempotency-Key`, ручной повтор с тем же ключом после 502 и отдельная обработка 409/422/502. При `no_charge_id`/`gave_up` доступна поддержка, «Возобновить» отсутствует.
- Удалены неработающие Telegram deep links и добавлен тест-guard на `apps/web/src` и `packages/ui/src`.
- Квота совместимости и её форматтер работают из `GET /compatibility`; результат перечитывает `/compatibility` и `/me` после `ready`/`failed`.
- Добавлен список сохранённых результатов совместимости в кабинете, переход к результату и возврат к списку.
- Шаги рендерятся как список при маркерах и как проза без них; warnings показываются только для `trimmed`; дисклеймер выводится отдельным тихим абзацем один раз.
- Юридическая строка сверена с `legal.md` §4 п.5; SHA обновлён, тест не ослаблялся.

## Контракт

- `POST /api/v1/subscription/cancel`, обязательный `Idempotency-Key`, ответ `200` и ошибки `409`/`422`/`502` согласно OpenAPI 1.6.5.
- Состояние подписки читается из `GET /me.subscription`.
- Квота и список совместимостей читаются из `GET /compatibility → quota/items`.
