# SPEC — что строим

Telegram Mini App: пользователь вводит дату, время и место рождения → получает натальную карту (Swiss Ephemeris) и персональный разбор из 6 глав, написанный LLM по рассчитанным фактам. Ежедневный прогноз приходит в бот.

Цель первой версии: от открытия до оплаты ≤ 3 минуты, возврат на следующий день.

Монетизация — Telegram Stars (XTR): подписка и разовые разборы. Цены и правила платежей — `payments.md`.

Аудитория: RU, 18+, женщины 22–40.

## Сценарии

**1. Онбординг и карта.** Приветствие с дисклеймером (18+, развлекательный контент) → согласие на обработку ПДн (галочка + ссылки на политику и оферту, тексты — `legal.md`) → дата → время («точно» / «примерно» / «не знаю») → место рождения (поиск города) → карта: колесо, Солнце/Луна/Асцендент, тизер разбора, «поделиться» (картинка + ссылка на бота, а не голая ссылка на SVG). При неизвестном времени карта строится, дома и Асцендент помечены как нерассчитанные.

**2. Покупка разбора.** Тизер (3 строки + размытие) → «Открыть полностью — 149 ⭐» → оплата → экран «готовим» с прогрессом → через 30–90 сек пуш и готовый разбор (6 глав + PDF).

**3. Подписка.** Пейволл: неделя 149 ⭐ / месяц 399 ⭐ / год 2 990 ⭐. После оплаты полный прогноз, 5 вопросов в день, совместимость 1/мес. Отмена автопродления — из приложения (`POST /api/v1/subscription/cancel`, контракт 1.6.5): доступ остаётся до конца оплаченного периода; настройки Telegram тоже работают. Купленный разово разбор не зависит от подписки и не исчезает с её окончанием. По запросу пользователя он удаляется вместе с остальными данными (см. `legal.md`); звёзды за разбор, удалённый по запросу пользователя, не возвращаются.

**4. Ежедневный прогноз.** `GET /api/v1/forecast/today` (с итерации 30) на местную дату места рождения: четыре раздела — день в одном предложении, где легче, где осторожнее, один шаг. Факты (Луна на полдень, фаза, ретро, транзиты, управитель дня, окна времени) считает движок детерминированно; текст пишет модель **один раз в сутки на человека**, повторный запрос отдаёт сохранённое. Без подписки модель не вызывается: `200 facts_only` с тремя фактами. Провал генерации — `503`, вчерашний текст не отдаётся никогда. Пуш в бот — 08:00 по поясу места рождения (ночной джоб `engagement`).

**5. «Спроси карту».** Вопрос по своей карте: 3 в сутки по подписке (`QUESTION_DAILY_LIMIT`), без подписки — `403 subscription_required` (решение владельца, итерация 30). Ответ — три раздела: ответ 150–300, почему 250–400, что сделать 150–250 знаков. Запрещённые темы (медицина, юристы и налоги, кредиты и инвестиции, смерть и болезни, вопросы про третьих лиц, 18+) отклоняются **до** вызова модели: постоянный текст отказа и причина из закрытого списка, квота не тратится.

**6. Возврат в приложение.** Пользователь с готовой картой при открытии попадает сразу на экран карты (`onboarding_step=done`, `chart_id` из `GET /me`), а не на приветствие. Онбординг не проходится заново.

**7. Удаление данных и хранение вопросов.** Тексты вопросов «спроси карту» хранятся до удаления аккаунта и возвращаются только владельцу; в логи, события и аналитику они не попадают — там `question_hash` (`sha256[:16]`), длина и тема. Прогнозы дня хранятся как факты дня и готовый текст (нужны, чтобы показать день повторно без нового вызова модели) и удаляются тем же `DELETE /me`.

**7.1. Удаление данных.** Кнопка в кабинете → двойное подтверждение → удаление профиля, карт, разборов, прогнозов, вопросов. Подписка при этом отменяется, доступ закрывается сразу, оплаченный период не возвращается — это сказано в диалоге подтверждения до нажатия. Автопродление в Telegram отключается вызовом `editUserStarSubscription` (ошибка Bot API удаление не блокирует, повтор — джобом). Обезличенная история платежей сохраняется для бухучёта и возвратов; платёжный идентификатор снимается через 30 дней (окно возврата).

## Экраны (9)

| # | Экран | Главное |
|---|---|---|
| 1 | Welcome | дисклеймер виден без скролла |
| 2 | BirthDate | валидация 18+ |
| 3 | BirthTime | 3 варианта, честное предупреждение о точности |
| 4 | BirthPlace | поиск от 2 символов, часовой пояс из места |
| 5 | Chart | колесо + 3 карточки + тизер + шеринг |
| 6 | Report | оглавление, главы, PDF |
| 7 | Paywall | 3 тарифа, оплата через `openInvoice` |
| 8 | Forecast | текст, фокус, «спросить карту» |
| 9 | Settings | подписка, квоты, удаление данных, поддержка |

## Данные (Postgres)

`users`, `profiles` (дата/время/место/согласие), `charts` (jsonb + `input_hash`), `reports` (статус, главы, стоимость LLM), `forecasts` (ночной джоб удержания), `asks` (вопросы `engagement`), `daily_forecasts` (прогноз дня: уникально `user_id + local_date + prompt_version`, факты дня, стоимость), `questions` (вопросы «спроси карту»: `question_hash`, `idem_key`, один `pending` на человека), `question_usage` (дневная квота по местной дате), `subscriptions`, `payments` (уникальный `telegram_payment_charge_id`), `entitlements` (разовые покупки), `quotas`, `events`.

Подробные поля — на усмотрение BACKEND, но: `payments.telegram_payment_charge_id` уникален, `forecasts(chart_id, date)` уникален, у `charts` есть `input_hash` для идемпотентности.

## Астро-движок (`packages/astro`)

- `calcChart(input)` — планеты, дома Плацидуса, аспекты, баланс стихий. Плюс `transitsFor(date, chart)` для прогноза.
- `llmContext(chart)` — только факты в JSON. Модель не считает, а переводит.
- `renderWheel(chart)` — SVG, поворот по Асценденту.
- Детерминизм: одинаковый вход → одинаковый JSON. `time_known=false` → дома и ASC = `null`.
- Эфемериды локально, без сети. Прототип уже есть: `astro/engine.py`.
- Swiss Ephemeris под AGPL: до покупки коммерческой лицензии работает флаг `ASTRO_ENGINE=fallback`.

## Генерация текста

Две стадии: план (6 глав × 3–5 тезисов, каждый со ссылкой на позицию карты) → главы по 400–700 слов. Ответы валидируются схемой, при невалидном JSON — один ретрай, потом `failed` + автовозврат звёзд.

Текст: «ты», без запугивания и лести, в каждом разделе ссылка на конкретную позицию карты. Запрещено: предсказания событий с датами, медицина, юридика, гарантии денег, «смерть/болезнь/развод» как утверждения.

Стоимость: разбор ≤ $0.35, прогноз ≤ $0.003 с обязательным кэшем по `(chart_id, date)`. Пишем `llm_cost_usd` на каждый вызов.

## Технические рамки

- `pnpm` монорепо: `apps/web` (React+Vite), `apps/api`, `apps/bot`, `packages/astro` (Python, pyswisseph), `packages/shared`.
- Авторизация — только валидация `initData` (HMAC-SHA256, `auth_date` ≤ 24 ч). Никаких JWT в localStorage.
- p95 API без LLM ≤ 400 мс, `POST /charts` ≤ 800 мс, разбор ≤ 120 с. Бандл фронта ≤ 350 КБ gzip.
- Rate-limit: 60 req/мин чтение, 10 req/мин мутации.
- Прогнозы генерируются ночным джобом пачкой, не в момент запроса.
- Все проверки доступа — через одну функцию `getEntitlements(userId)`.

## Перед публикацией

Дисклеймер 18+ и «развлекательный контент», политика ПДн с согласием, оферта с правилами возврата, работающий `refundStarPayment`, лицензия Swiss Ephemeris или флаг `fallback`.
